# 聊天交付修复必须同时发布 APP 与 Channel 模板镜像

> 状态：**已采纳（当前规范）**

聊天交付修复作为一项逻辑变更，同时包含 APP 发布镜像和 Channel 模板镜像。APP 负责关联和清理请求；Channel 模板镜像确保模型回复实际作为出站事件投递。只部署其中任一镜像，都会留下另一种尚未消除的故障模式。每个发布账号都应根据提供的 Channel 模板镜像手工创建自己的 Template，并且只使用该账号拥有的资源进行验证。Channel 模板镜像是基于该账号已核验的当前不可变 digest 构建的增量补丁，只修改回复投递所需的 Channel Runtime 文件。

## 已考虑的方案

- 仅部署 APP 镜像：不采用。APP 的关联逻辑无法修复 Channel 没有产生出站回复的问题。
- 仅部署 Channel 模板镜像：不采用。并发 APP 请求仍可能消费到错误的出站回复。

## 后果

发布负责人提供带版本的镜像和验证证据，但不会在其他发布账号中创建或替换 Template。仅测试镜像启用聊天追踪日志；现有在线热修复会保留，直到替代 Template 在新 Sandbox 上验证成功。
