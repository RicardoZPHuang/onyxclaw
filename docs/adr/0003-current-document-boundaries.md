# 当前文档与历史证据的边界

> 状态：**已采纳（当前规范）**

## 背景

仓库同时经历过本机验证、云端故障排查、镜像构建方案和多份阶段性提案。若把已完成的
方案、一次性实测记录与当前操作指南并列，维护者无法判断哪个文件能指导下一次变更，也容易把
历史环境细节误当作可复用配置。

## 决策

- `README.md` 是当前入口；它指向当前规范、当前指南和历史证据。
- `CONTEXT.md` 只定义项目术语；ADR 记录仍有效、难以逆转的架构或治理决定。
- 架构、构建、配置、运行时和本地开发分别由一个标有“当前规范”或“当前指南”的文件负责。
- 代码与回归测试是实现行为的权威来源；文档不得以历史叙述覆盖它们。
- `docs/huaweicloud-sandbox-resume-bug-tracker.md` 是唯一保留的历史证据文件。它只保留理解结论所需的脱敏时间线和可追溯镜像 `tag@digest`，不保留 endpoint、内部路径、Template 或 Sandbox 标识、拓扑细节与凭据。
- 已被提取的阶段方案、实施总结、旧 onboarding 和静态调查报告直接删除；不建立仓库内历史归档目录。

## 已考虑的方案

- 将全部旧文档移动到 `docs/history/`：不采用。历史文件仍会被误当作当前操作依据，也会继续携带过时环境细节。
- 保留多个并列的当前方案：不采用。相同主题出现多个“当前”来源时，维护者无法可靠判断权威文件。

## 后果

新增或修改文档时，必须声明其状态，并更新 README 导航；若变更影响术语或长期治理边界，
同时更新 `CONTEXT.md` 或新增 ADR。发现历史证据中出现环境标识或敏感运行细节时，应在保留
结论和必要镜像可追溯性的前提下先脱敏，再继续维护。
